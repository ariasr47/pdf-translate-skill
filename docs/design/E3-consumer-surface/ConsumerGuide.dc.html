# Running one document from Python Contents: before you start · the seven calls · what each returns · the files on disk · refusals · progress and cancellation · threads · determinism · what this library never does For an engineer with no context. Every code block runs as written against the corpus fixture. The CLI paths in README.md do the same things; this document is for calling the stages directly. ## Before you start — three things that cost hours 1. `lang` is a BCP 47 tag: `"ja"`, never `"Japanese"` or `"日本語"`. ISO 639-2 (`"jpn"`) is accepted. A value that is not a tag makes the metadata gate REVIEW rather than silently passing. Full rules and the whole mapping format: `references/translations-format.md`. 2. The Han-forms gate needs two reference faces — `NotoSansJP-VF.ttf` and `NotoSansSC-VF.ttf`, under one directory you pass as `reference_fonts=`. Absent, the gate reports REVIEW and cannot reach PASS. Exact names, where to get them, and what the gate does without them: `references/fonts.md`. 3. Nothing here reaches the network. Fonts, reference faces and any terminology lookup are files you provide. Issuer lookup belongs to whoever authors the mapping, never to this library. ## The seven calls strip → extract → [you author the mapping] → prepare_font → retypeset → verify → field_fonts. Each takes explicit paths, returns a result object, and raises a typed exception when it refuses. No `os.chdir`. No `sys.exit`. No `print` — it logs on `pdf_translate`, and attaches a NullHandler, so it is silent until you attach a handler. No model calls: this library does not translate. It strips, extracts, places, and judges.
