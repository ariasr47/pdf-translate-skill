A silent twin per stage
The repository already solved this twice. verify/run_verify and qa_check/run_qa are a loud function and a silent one returning a verdict. E3 finishes the pattern rather than inventing one.
Why not simply silence the stage functions. Measured in tests/test_pipeline.py: 177 redirect_stdout blocks, and 128 of them wrap a library function directly — verify.verify( 64, retypeset.retypeset( 55, prepare_font.prepare_font( 5, field_fonts.field_fonts( 2, strip_text.strip_text( 1, pipeline.propose_merges( 1. Only ~41 wrap a main(). Making those functions quiet breaks roughly 200 assertIn calls at once.

The silent one — what a service calls
log = logging.getLogger(__name__) def run_retypeset(…) -> RetypesetResult: """Silent. Returns data. Raises on refusal.""" log.info('placed %d runs on p%d', n, pno) … raise GlyphError(page=pno, char=ch)
Silent because no handler is attached — not because stdout was swapped. That is what makes it safe under threads.
The loud one — byte-identical to today
def retypeset(stripped, segf, trf, out): """Legacy shape: prints, returns an int.""" with _console(): # handler on, then off try: run_retypeset(stripped, segf, trf, out) except PdfTranslateError as exc: log.info(exc.console_line) return exc.exit_code return 0
Same name, same arguments, same printed bytes, same return code. Every one of the 128 blocks keeps passing.
No test churn
All 177 blocks and all 282 assertIn calls are untouched. New tests are added for the run_* twins.
The stdout swap dies
run_verify drops redirect_stdout (verify.py:2124) and becomes silent the same way its six new siblings are.
One stage at a time
Each twin is its own commit with the parity runner as the ratchet. A 172-site single commit would be unreviewable.
The cost this design accepts: two entry points per stage, and a deprecation story the consumer guide has to tell — run_* for a service, the bare name for the CLI and for anything written against today’s shape. C10 says the package never prints, and after this it does not: the loud wrapper logs too, it just attaches a handler first.
