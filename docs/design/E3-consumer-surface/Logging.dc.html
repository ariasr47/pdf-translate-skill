C1 + C10 + the parity acceptance, in one move
The stages log. The CLI prints.
One change satisfies “no printing unless asked”, “through the logging module, never print”, and “the eleven CLIs byte-identical” at the same time — and leaves 351 test assertions untouched.
Every stage module, at the top
import logging log = logging.getLogger(__name__) # and in pdf_translate/__init__.py logging.getLogger("pdf_translate").addHandler( logging.NullHandler())
The stdlib idiom: a library attaches a NullHandler and never configures logging. Silent by default, in-process, thread-safe.
Every call site — 141 of them
- print(f'PASS field parity') + log.info('PASS field parity') - print(f' (could not write {path}: {exc})') + log.info(' (could not write %s: %s)', path, exc)
Level INFO for everything a gate or stage says today — the console is the contract, so nothing is re-levelled as part of this move.
Every CLI main(), at the top — the only place output is configured
def _console(): """Attach the one handler that reproduces today's console exactly: the bare message, no level, no logger name, no timestamp.""" h = logging.StreamHandler(sys.stdout) h.setFormatter(logging.Formatter("%(message)s")) pkg = logging.getLogger("pdf_translate") pkg.addHandler(h) pkg.setLevel(logging.INFO)
The tests do not move
All 351 capture idioms wrap a stage’s main(), not the library function. main() still writes the same bytes to stdout, so every assertIn passes unchanged. The bill is near zero.
The stdout swap goes away
run_verify is silent today by redirect_stdout (verify.py:2124) — it swaps sys.stdout process-wide. Under C5 that is a live bug. Silent-by-default deletes it.
verify and run_verify converge
They differ at the library level today: one prints, one redirects. Afterwards there is one function and one question — is a handler attached.
What proves it: the parity runner E3 already asks for — every one of the eleven CLIs run before and after, stdout captured, diffed byte for byte. It is the same instrument dev/probes/verdict_parity_runner.py already uses for gate work, widened from verify to all eleven. A single differing byte fails the build, which is exactly the guarantee the product needs before it pins a version.
