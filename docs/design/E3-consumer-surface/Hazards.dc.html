Four hazards, in severity order
C5’s status note says “no os.chdir anywhere”, which is true and not the whole story. These are what a thread pool actually hits.
1
A process-wide sys.stdout swap, inside a library call
breaks under threads
verify.py:2124 with redirect_stdout(io.StringIO()):
run_verify is silent by replacing sys.stdout for the duration of the call — not by the gates being print-free. sys.stdout is global, so while one thread is inside run_verify, every other thread’s output is swallowed into that buffer. Two concurrent jobs and the second job’s console vanishes.
Fix: free. The logging move deletes the wrapper — silence becomes “no handler attached”, which is per-logger, not per-process.
2
A live working-directory dependency
C1 violation
retypeset.py:862 arch = pymupdf.Archive('.')
That archive is handed to every insert_htmlbox call in both loops. Any relative resource reference inside authored HTML resolves against the process’s cwd — not the mapping’s directory, not a caller-supplied root. C1 says “no dependence on the working directory”, and grep confirms there is no os.chdir to blame. Two more cwd-relative defaults sit beside it: shaping_probe.py:227 builds its own Archive('.'), and extract_segments.py:520 defaults outdir='.'. All three are the same fix.
Fix: anchor the archive to the mapping’s directory, with a keyword-only resource_root= to override. Behaviour is unchanged for every job whose cwd is already the work dir — which is every job the CLI runs.
3
Two jobs, one scale_report.json
silent data loss
retypeset.py:1379 os.path.join(os.path.dirname(os.path.abspath(out)), SCALE_REPORT)
A fixed filename beside the output. Two jobs writing their outputs into one directory — the obvious thing a service does — overwrite each other’s report with no error and no warning. The report is also written non-atomically, without the temp-and-replace and stale-removal that write_report gained in v53 after PR #7.
Fix: the library returns the runs in RetypesetResult and writes a file only when given an explicit scale_report= path; the CLI passes today’s path, so the console and the file both stay identical.
4
Determinism is unmeasured, not known-broken
measure first
retypeset.py:1387 doc.ez_save(out) # no arguments retypeset.py:354 apply_document_metadata # set_metadata() rewrites /Info; /ID untouched
No timestamp parameter exists. The metadata pass copies the source’s doc.metadata, pops only format and encryption, and calls set_metadata() — which rewrites the whole /Info dictionary, carrying the source’s /CreationDate, /ModDate and /Producer through unchanged. Only /ID is genuinely untouched, which makes it the likeliest variable byte. Whether two runs differ at all is not known: it has never been probed here.
Fix: a probe before a design — the same order task F and the Han-forms gate used. Run one fixture twice, diff the bytes, and name every differing offset. Only then decide whether timestamp= plus a content-derived /ID is sufficient, or whether the save call itself has to change. Do not write the C7 code from this artboard.
