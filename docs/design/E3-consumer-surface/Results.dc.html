Frozen dataclass, tuple fields, to_dict() carrying schema and version — the shape VerifyVerdict has had since v51.
C3 is cheaper than its own status note says. The note reads “the extractor’s warnings and the strip result are printed, not returned”. Measured at v56, both are returned and also printed: strip_text() returns a report dict (encryption, perms_removed, certified, leftover_text, counts) and extract_segments() returns segments, warnings, cores, document, pages. The data exists; it needs an envelope and a type, not an excavation.

The one that is not just an envelope
scale_report.json is a bare JSON list
# retypeset.py:1379 — today report = os.path.join(os.path.dirname(os.path.abspath(out)), SCALE_REPORT) with open(report, 'w', encoding='utf-8') as f: json.dump(sorted(scaled, key=lambda r: (r['page'], r['key'])), f, …)
Three problems in four lines. There is no envelope, so no place to put schema without changing the file’s top-level type. There is no atomic write — no temp-and-replace, no stale removal — the protections write_report gained in v53 after PR #7, never carried across. And the path is a fixed name beside the output, so two jobs writing their outputs to one directory silently overwrite each other’s report.
Wrapping it is a breaking change to a published file format. That is a decision, not a detail — it is Question 2 on the “Decide first” artboard. It is cheapest now, before the product pins a version and builds goldens on the current shape.
