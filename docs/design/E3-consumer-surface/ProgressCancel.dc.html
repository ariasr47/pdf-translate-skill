Progress and cancellation
Nothing today: no callback parameter, no cooperative check in either loop. It is also the cheapest item in the epic, for one structural reason.
“Leaving no partial file at the output path” is already true. retypeset has exactly one save — doc.ez_save(out) at retypeset.py:1387 — after both loops and after the metadata pass. Every refusal path already returns before it. So cancelling between pages cannot leave a partial output; the guarantee C4 asks for is a property of the existing structure, not something to build.

The detail that decides the counter
retypeset runs two loops, not one: a per-page placement pass, then a separate per-merge-job pass over the same document. A naive progress(page, page_count) would reach 100% and then keep working, which is the worst thing a progress bar can do.
So total is pages + merge jobs and done is monotonic across both — one fraction, never resetting, never overrunning. A caller who wants the phase can read it from RetypesetResult afterwards; a progress bar does not need it.
