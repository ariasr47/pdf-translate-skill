## 1. Verdict

**The bet is right. The next investment is the wrong shape.**

Right: strip-and-retypeset, field parity as an invariant, refusal over
guessing, provider neutrality, and a loop that turns measured defects into
fixtures and gates. The 2 September canary is the proof: three models, three
approaches, zero structural escapes. The September 2026 market still has
nobody preserving fillable forms (§3.1). The niche is real and unoccupied.

Wrong shape: three days, 39 commits and 158 tests have proven the pipeline
on constructed fixtures and **one** real document. What the product needs
now is evidence and reach, not another gate:

1. **Real-world coverage is unmeasured.** n = 1 (FL-150) plus a two-page
   synthetic canary. The refusal rate, crash rate and warning noise on
   public forms — IRS, USCIS hybrid-XFA, state courts, EU, hospitals,
   manuals — is unknown. This is the largest risk to the product and the
   cheapest to measure.
2. **The product is not installed anywhere current.** The only installed
   copy is on a Windows box at version 16 against 30; there is no plugin
   manifest, so every sync is a manual copy. A skill nobody runs is not a
   product.
3. **`SKILL.md` is over the limits that matter.** 550 body lines, about
   4,600 words, and **about 7,300 tokens on invoke** as `claude plugin
   details` measures it, against Anthropic's "under 500 lines" and the
   spec's "under 5,000 tokens". It grew about 60% since the 1 September
   audit measured 340 lines. The cost is mechanical, not stylistic: after a context compaction
   Claude Code re-attaches only the **first 5,000 tokens** of an invoked
   skill, so on a long job the tail — verify, field fonts, deliver — is
   exactly the part that disappears.
4. **The eval is manual.** The canary took a person a day to run and score.
   `claude plugin eval` (present in the 2.1.236 build on this machine) runs
   cases with a no-plugin baseline arm, an LLM grader, a JSON report and a
   threshold exit code; the canary's objective half (`score.py`) is already
   a grader.
5. **Status has three sources that disagree.** The README said 154 tests;
   the audit HTML shows 18 findings as Open that are all fixed;
   `RESEARCH-AND-FINDINGS.md` §12 said the canary had not been run. The
   trivial ones are fixed in this commit (§6).

The program rule — *do not invent the next row; wait for the canary* — is
right for **gates** and has quietly become the only source of roadmap.
Packaging, corpus, skill length and eval automation are never a "silent
PASS class", so under that rule they never get a row. Grooming here means a
second lane with the same discipline (one sitting, a closed bar, non-goals,
proof) and a different trigger: product evidence rather than a model's
defect.

## 3. Research, September 2026

### 3.1 Market: the niche stands

- A seven-platform 2026 review (Reflo, DeepL PDF, Adobe Acrobat AI, Google
  Translate PDF, Smallpdf, ChatGPT file upload, PDFelement) scores layout
  and multi-column handling and **never mentions form fields, AcroForms,
  bookmarks or links** [1]. It is Reflo's own review, so weight the
  rankings accordingly; the absence of forms from the rubric is the point.
- Adobe Acrobat's AI Assistant translates in the chat panel; third-party
  reviews report it works segment by segment and does not produce a
  translated file [2].
- BabelDOC, the reference open-source engine, has `--skip-form-render` and
  an OCR workaround, a glossary CSV, dual and mono output and a translation
  cache, and talks only to OpenAI-compatible endpoints; no AcroForm,
  bookmark or tagged-PDF handling is described [3]. pdf2zh 2.0 lists none
  either [4].
- Every serious competitor has paragraphs, glossaries and bilingual output;
  this repo now has paragraph mode, a per-job glossary input and a
  bilingual reading copy too. The differentiators remain forms, refusal
  gates and provider neutrality.

Consequence: keep the positioning. Do not chase layout-recognition models.
The strip-and-retypeset invariant is the moat and the risk at once, which is
why the wild corpus matters.

### 3.2 Anthropic guidance, and where the skill sits against it

- Best practices [5]: SKILL.md body **under 500 lines**; split into
  references one level deep; descriptions in third person saying what
  *and* when; **build evaluations before extensive documentation**; test
  with Haiku, Sonnet and Opus (the canary does exactly this — keep it).
  Checklist items the skill misses: the body length; and the "at least
  three evaluations" exist in `evals/evals.json` but have never run under a
  harness.
- Agent Skills specification [6]: six frontmatter fields; instructions
  **under about 5,000 tokens recommended**; `compatibility` at most 500
  characters. The skill's frontmatter is spec-clean (name, description,
  license, compatibility, metadata.version), which matters: Claude
  Code-only fields would stop the skill loading in claude.ai and the API.
- Claude Code extensions [7]: `when_to_use` (appended to the description,
  1,536-character cap for the pair), `paths` (auto-activate on file globs;
  `**/*.pdf` is a candidate), `allowed-tools`, `context: fork`,
  `disable-model-invocation`. Compaction keeps the first 5,000 tokens of an
  invoked skill and 25,000 across all skills [7] — the mechanism behind
  verdict item 3.

### 3.3 Packaging and eval tooling (checked on this machine)

- `claude` 2.1.236 is installed here. `claude plugin validate --strict`
  **passes** a root-as-plugin manifest (`.claude-plugin/plugin.json` with
  `"skills": ["./"]` or `["./pdf-translate"]`) built in a scratch copy, so
  no restructuring of `pdf-translate/` is needed. Discovery works too:
  `claude --plugin-dir <scratch> plugin details pdf-translate` lists the
  skill from the `["./"]` manifest and reports its cost — about 160 tokens
  always-on, about 7,300 on invoke. Installing from the GitHub marketplace
  is what the packaging sitting still has to show. Docs: [8].
- `claude plugin eval` exists: cases as `evals/**/case.yaml` (or
  `prompt.md` plus `graders/*.md`), a with/without baseline arm
  (`--ablation`), an LLM judge (Haiku by default, overridable), `--runs`,
  `--threshold` (exit 1 below it), `--json`, an HTML report,
  `--max-cost-usd`. This is the harness the 1 September audit said did not
  exist. The skill-creator's `evals.json` format (`id`, `prompt`,
  `expected_output`, `files`, `assertions`) [9] is a different,
  agent-driven format; the repo's `evals.json` matches it minus
  `assertions`.

### 3.4 Libraries

- PyMuPDF 1.28.2 (installed). 1.28 removed linearization and fixed
  combo-box choice values and widget rotation; no Story-engine or
  TextWriter changes since 1.26 [10]. The `<1.30` pin holds.
- pikepdf 10.12. Still no structure-tree API (issue #461 open) [11], so
  rebuilding tags after strip stays parked; removing the orphaned tree with
  `/MarkInfo /Marked false` remains the honest output.

### 3.5 The real-world form landscape

IRS and most USCIS forms are AcroForm. Several USCIS forms are **hybrid XFA
plus AcroForm** (I-821, N-400, G-28, I-90, I-131, I-864) and older ones are
pure XFA [12]. Strip already removes the XFA layer; what the AcroForm layer
looks like once XFA is gone on those files is unmeasured. That is the first
thing the wild corpus should answer.

## 4. Hypotheses to measure before they become rows

Recorded so the wild-corpus sitting looks for them. None is a row until it
shows up in a real file.

- **H-A Visible annotation text.** Extraction deliberately ignores
  annotation appearances (goal 17). A FreeText note, a Stamp, or a Link
  with a visible caption therefore ships untranslated with every gate
  green. Probe: a form with one FreeText annotation.
- **H-B Hybrid XFA.** After XFA removal, does the AcroForm render match
  what Acrobat showed? Probe: one USCIS hybrid form.
- **H-C Real fonts.** Type3 bitmap fonts; symbolic fonts used for check
  marks (Wingdings, ZapfDingbats — pass-through or "translated"?); CID CFF
  with custom encodings; text converted to outlines (should hit the
  refusal path).
- **H-D Scale.** The invisible-text oracle strips and renders every page:
  0.31 s for 4 pages measured, so about 8 s per 100 pages — acceptable.
  Story-engine placement per line on a 100-page manual is unmeasured.
- **H-E Compaction.** A long job under Claude Code loses the skill's tail
  after compaction (§3.2). The SKILL.md sitting is the fix; canary run 2
  should include one deliberately long session to observe it.

**P3 — `SKILL.md` under 500 lines and about 5,000 tokens.** *Done when:*

## 8. Addendum — the wild corpus ran the same evening

P1 closed with the user's approval to download. Seventeen public
born-digital PDFs (`dev/wild/SOURCES.md`; four more were blocked for
non-browser clients), 449 pages, eight of them hybrid XFA, through the
shipped strip and extract in one subprocess each: **17/17 `translate`,
zero crashes, zero timeouts**, the 126-page IRS booklet in 37 s; every
character left after strip is annotation text (captions, values); page-1
renders before and after keep every rule, box, band, seal and image. The
verdicts were right. What the corpus found is friction on real documents,
measured in `dev/wild/ANALYSIS.md`: the `right-aligned` warning proposes
11,507 segments of mostly justified text for `right` (row 21); merge
candidates carry no `kind` and were miscounted by the first tool keyed on
it (row 22); and 6,191 warnings printed one line at a time, 1,093
write/find/say hits on one booklet, is an authoring loop that does not
scale past a four-page form (lane B row P6). Hypotheses: hybrid XFA
answered for the AcroForm layer, scale answered, annotation text and
exotic fonts unmeasured because none of the seventeen files has them.
Order now: 19 → 20 → 22 → 21 → P2 → P6 → P3 → C2 → P4.
