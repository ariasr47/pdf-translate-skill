## What was removed, and why each was dead

**1. The second untranslated pass in legacy retypeset.** Before drawing,
retypeset collects every segment with no translation and refuses them all
at once: `MappingError`, with refusal key `untranslated`. Inside the drawing
loop, a second copy of that check kept its own list, console block and
raise. It could never fire:
- **Same segments.** Both walk the same `by_page`. Nothing between them
  changes `by_page`, `T` or `skip`; the only mention of `by_page` in between
  is the drawing loop's own read.
- **Same skips first.** The drawing loop skips a segment in `skip`, and
  draws an override's parts and `continue`s, before it reaches
  `jp = T.get(core)`. The early pass skips the same two.
- **Same test.** Both test `T.get(core) is None and not passthrough`, and the
  early pass always raises when it finds one.

So the drawing loop meets a missing translation only on a passthrough
segment, which it draws in Helvetica as before. The late refusal keeps
`'untranslated': []`, so every refusal from that site has the same keys.

**2. `_run_typography`'s `resource_root`.** The parameter was accepted and
never read. `run_retypeset`'s own `resource_root` stays: the legacy path
resolves authored HTML against it, and capture bundles record it.

**3. A duplicate path helper.** A nested `_same_file` repeated the module's
`_same_path`, except for its fallback when `os.path.samefile` raises:
`abspath` equality against `normcase(realpath)`. Its one use is the
alias-role check. All four role faces are opened with
`pymupdf.Font(fontfile=...)` just before it, so a missing file fails there
first. At the check `samefile` succeeds, and the two helpers agree.

**4. `verify.load_segments_for`.** It has had no caller in the repository
since `fe32df6`. It is not in `pdf_translate`'s public names. It is also
not among the five names the app uses: `import pdf_translate`,
`extract_segments`, `strip_text`, `retypeset`, `WidgetTextError` and
`strip_text.widget_text_scaffold`.

**Records:** the quick-wins row in `docs/REQUESTS-from-product.md`. The
version goes from 73 to 74. No DECISIONS row: nothing about behaviour is
ruled.

## Independent verification

An adversarial pass on a different model (Sonnet) set out to prove that
something removed was live. It worked from `git archive` copies of
`8a92574` (v73) and `cb3a670` (v74), with its own tripwired base. Verdict:
**PASS**.

**1. The late untranslated pass.**
- **By reading.** It read the whole legacy path. No line writes a segment's
  fields, `T` is assigned once, and `skip` and the override index are built
  once. Merges delete segments from `by_page` before both passes.
- **Eleven adversarial legacy jobs,** run on the base, the tripwired base
  and the fix:
  - an override masking a missing core;
  - a passthrough numeric core;
  - a rotated missing core;
  - a missing core on page 2;
  - duplicate missing segments;
  - `cancel()` true from the start;
  - a fabricated segment on page 99 of a one-page document;
  - an empty-string translation;
  - a skipped, missing text;
  - a complete and an incomplete baseline.
- **What happened.** The tripwire never fired. Exceptions, refusals, exit
  codes and outputs were identical across the three. The page-99 segment is
  refused by the early pass, which walks every page in `by_page`, while
  drawing walks only the document's pages.
- **Output.** A successful legacy job's PDF was byte-identical, base
  against fix.
- **Its own suite run.** The tripwired base's full suite, corpus rebuilds
  included, never fired the tripwire either.

**2 and 4.** `resource_root` is read nowhere in `_run_typography`, whose
one call is updated. `load_segments_for` has no caller anywhere in the
repository, and is in neither `__all__` nor any reference doc.

**3, a note.** The two helpers' fallback formulas can disagree in
isolation. That happens for one file with two spellings (`/var` and
`/private/var`) when it is deleted between being opened and being compared.
At the call site all four faces are opened on the line before, so reaching
the fallback needed the font loader patched to delete a file. Even then,
the only effect is whether a diagnostic log line prints: refusals, exit code
and output are unaffected.
