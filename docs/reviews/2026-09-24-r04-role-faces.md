## The defect

MuPDF builds an embedded font's `/ToUnicode` by reverse-mapping its cmap.
When two code points share one glyph, it can report the wrong one. Arial's
space, for example, comes back as NBSP (`failure-modes.md` §14). After
saving, legacy retypeset rewrites `/ToUnicode` to the authored code points,
but it passed only `fonts['regular']` and `fonts['bold']` to
`canonicalize_text_layer`.

A run drawn in the italic or bold-italic face therefore kept MuPDF's
mapping. The italic and bold-italic cuts of Arial, Times, Georgia, Verdana
and Courier New share their space and NBSP glyphs, and so do 46 of 196
local faces. With any of them, a correct page extracted every space as
U+00A0. Verify then failed it twice:
- **"text layer is not canonical"**;
- **"missing translation targets"**.

The only workaround was to drop the italic faces, which loses the italics
the docs promise.

## Reproduced before building

The face was a copy of Noto Sans Italic whose cmap also sends U+00A0 to the
space glyph. The source line was drawn in Times-Italic, so the segment is
italic, and the italic role was given that face.
- The run is drawn in `NotoSans-Italic`, as it should be.
- The text layer reads `Lea\xa0el\xa0aviso\xa0con\xa0cuidado\xa0hoy.`
- Verify exits 1 with both FAILs above.

## The change

In `pdf_translate/retypeset.py`, legacy canonicalization gets every role
face that can have drawn a run:
`list(dict.fromkeys([f_regular, f_bold, f_italic, f_bold_italic]))`.
A face that drew nothing is a no-op. The drawing itself is untouched.

**Docs:** `references/failure-modes.md` §14 says the rewrite covers all four
roles.

**Records:** a `docs/DECISIONS.md` row, and the quick-wins row in
`docs/REQUESTS-from-product.md`. The version goes from 66 to 67.

share the space glyph. For each line, the run must be drawn in the right

NBSP. **Green.** Both pass, with the font-role and canonical-layer classes:
12 tests.
