## The finding: the notice and the leak scan contradict each other

`verify.py` on the shipped file, invoked neutrally, **exits 1**:

```
FAIL untranslated running text (1):
   p1: Field Trip Permission Slip
```

That English run is inside its own Spanish notice, and it is there because
`references/compliance.md` says the notice must name the form:
*"This is an unofficial translation of {form number / title}"*. Naming the
source title in the source language is right — the reader has to know which
form this translates.

So two things I added today disagree: **compliance.md tells the author to
put a source-language title on the page, and the leak scan reads it as an
untranslated phrase.** Fable resolved it with
`--allow field,trip,permission,slip` and said so in the delivery, which is
the correct move available to it. It should not have had to.

For a later sitting, in preference order:

1. A title quoted inside a notice is a write/find/say identifier by the
   skill's own rule — the reader must locate that form. `verify` could
   treat spans that match the original's `/Title` the way it already treats
   `Form`/`Schedule` names, and stop calling them leaks.
2. Failing that, `compliance.md` should warn that the notice trips the leak
   scan and name the allowlist.

Do not build either today.
